==========================
Training / retraining guide
==========================

``ts_weathernbeats`` is **inference-only at runtime**: it loads a pre-trained
artifact bundle and predicts.  The bundle is regenerated by the standalone
``train`` script.  USDF CPUs make NBEATSx training slow (~10-15 min for the
full ~80k-row history because every per-slot Ridge sample needs an NBEATSx
forward pass), so the recommended workflow is **train on a faster local machine
(GPU/MPS), then rsync the small bundle back**.

The bundle is tiny (~250 KB): a NeuralForecast checkpoint plus one joblib of
48 Ridge correctors and a ``metadata.json``.  Copying it is trivial.

Bundle layout
=============

::

    nbeatsx_ridge_v0.1.0/
        metadata.json          model version, training window, lib versions,
                               feature schema, slot count
        nbeatsx/               NeuralForecast.save() directory (Stage 1)
            NBEATSx_0.ckpt
            configuration.pkl
            alias_to_model.pkl
        ridge_slots.joblib     {phi: SlotModel} -- one scaler+Ridge per slot

Train on all data (production)
==============================

The training script uses **all** rows in the input (no train/test split) so the
live model sees the full history.  Two telemetry sources:

CSV (reproduces the SPIE fixture; columns ``timestamp,min,mean,max``)::

    train_weathernbeats \
        --csv /path/to/temp_history_jan2026_with_weather.csv \
        --output models/nbeatsx_ridge_v0.1.0

Live EFD (omit ``--csv``; pulls the 7-day window via the FeatureBuilder)::

    train_weathernbeats --output models/nbeatsx_ridge_v0.1.0

Useful flags
------------

``--n-slots N``
    Slots per solar day (default 48 -- the grid cadence).
``--stride S``
    Sub-sample issuance points by ``S`` grid steps when fitting the Ridge
    layer.  ``--stride 1`` (default) uses every issuance point -- most samples,
    slowest.  ``--stride 4`` is ~4x faster and still gives thousands of samples
    spread across all 48 slots; good for iteration.

Speed knobs (edit ``python/lsst/ts/weathernbeats/train.py``)
------------------------------------------------------------

- ``NBEATS_MAX_STEPS`` (default 700) -- training iterations; the dominant cost.
- On a CUDA/MPS box NeuralForecast auto-uses the accelerator; no code change.

Local-train + rsync runbook
===========================

1. On the **fast machine**, clone the repo and set up the environment
   (``neuralforecast``, ``torch``, ``scikit-learn``, ``pandas``, ``astropy``).

2. Copy the training CSV over (or point ``--csv`` at a local copy)::

       rsync -avz \
           usdf:/sdf/home/e/esteves/sitcom-analysis/rubin-twilight-forecast/data/temp_history_jan2026_with_weather.csv \
           ./data/

3. Train on all data::

       train_weathernbeats --csv ./data/temp_history_jan2026_with_weather.csv \
           --output models/nbeatsx_ridge_v0.1.0

4. rsync the finished bundle back to USDF (whole directory, ~250 KB)::

       rsync -avz models/nbeatsx_ridge_v0.1.0/ \
           usdf:/sdf/home/e/esteves/sitcom-analysis/ts_weathernbeats/models/nbeatsx_ridge_v0.1.0/

5. On USDF, point inference at it::

       run_weathernbeats --bundle models/nbeatsx_ridge_v0.1.0 --simulation-mode 1

Version pinning
===============

``NeuralForecast.load()`` and ``joblib.load()`` are sensitive to library
versions.  Train and serve with matching ``neuralforecast`` / ``torch`` /
``scikit-learn`` versions; the training versions are recorded in
``metadata.json`` (e.g. ``sklearn_version``).  The USDF conda env this was
verified against is ``lsst-scipipe-13.0.0`` (neuralforecast 3.1.5, torch 2.7.1,
scikit-learn 1.8.0, pandas 2.3.1, numpy 1.26.4).
